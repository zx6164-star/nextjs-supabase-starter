# 코딩 스타일 가이드

## 기본 규칙
- 들여쓰기: 2칸 스페이스
- 네이밍: camelCase (변수/함수), PascalCase (컴포넌트/타입)
- 함수는 30줄 이하 유지, 길어지면 분리
- 매직 넘버 사용 금지, 상수로 정의

## TypeScript
- `strict` 모드 준수, 암묵적 `any` 금지
- Supabase 쿼리 결과는 반드시 타입 지정 (`types/database.ts` 활용)
- 타입 단언(`as`)은 최소화, 불가피한 경우만 사용

## 컴포넌트
- 서버/클라이언트 컴포넌트 여부를 파일 최상단에서 명확히 (`"use client"` 유무)
- 하나의 컴포넌트는 하나의 책임만 (목록 렌더링과 폼 제출 로직 분리)
- Props 타입은 컴포넌트 파일 내 인터페이스로 명시

## 에러 처리
- Supabase 쿼리는 항상 `{ data, error }` 구조 분해 후 `error` 확인
- 에러 발생 시 사용자에게 실패 원인을 알리는 UI 표시 (무시하지 않음)
- 존재할 수 없는 상황에 대한 방어 코드는 작성하지 않음 (실제 발생 가능한 경우만 처리)

## 커밋 메시지
- 한국어로 작성, `타입: 설명` 형식 (예: `feat: 할 일 추가 기능 구현`, `fix: RLS 정책 누락 수정`)
